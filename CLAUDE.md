# unforgettable

A simple mobile-first web game that trains one habit: always put your things (keys, wallet, phone, tools) on their own fixed place, so you never have to search for them. Long-term goal: a daily practice game whose hints fade until the player's memory does the work. Source of truth is this repo; it is published as a public mirror in the user's website, the `hugoheefer/my-wiki` repo (Cloudflare Pages, static).

## Stack and layout (must fit my-wiki, user decisions 2026-11-16)

- Plain JavaScript ES modules with JSDoc types: no TypeScript, no bundler, no npm dependencies. There is no build step, so the mirror is a plain copy of the `app/` folder. A root `package.json` here is fine (this repo is not auto-built); it only holds `{"type": "module"}` and the `test` script.
- `app/` is the publishable folder: `index.html`, `css/`, `js/`. All links inside it are **relative**, so it works from `/unforgettable/` in my-wiki without changes.
- `tests/` holds `node --test` tests that import the modules from `app/js/`. Tests never go into the mirror.
- Tests: `node --test tests/*.test.mjs` (pass the glob; a bare folder does not work on every platform).
- Model on `pong` and `weather` in my-wiki: a thin glue file (`app/js/main.js`: DOM wiring only) and many small single-purpose modules of 20 to 300 lines, pure logic apart from DOM drawing, each with its own test file.
- Storage follows `pong-notice-store.js` in my-wiki: the module gets a storage getter injected and wraps access in try/catch, so a blocked localStorage never breaks the page.
- English UI. Port naming: role names (`Storage`, `Clock`, `RandomSource`).

## Design decisions (with the reason)

- **One command and its choices per screen, then Next** (user decision 2026-11-16, after trying the second version: "too much information on one screen, it is not clear what to do"). Every screen is a `Step` (`lead`, `command`, `choices`, `selected`); `play-flow.js`, `setup-flow.js` and `app-flow.js` produce the steps, `screens.js` draws any step the same way. A choice only selects; the action happens on Next. Short feedback (what happened, moves left, the plan) goes in the small `lead` lines above the command, never in separate panels. The result screen is the one place that lists several lines, because that is the feedback the player learns from.

- **Every text the player reads is in one module per language** (`app/js/texts/en.js`; user decision 2026-11-16: English for now, Dutch must be easy to add). Flows, views and the round get the texts injected; only `texts.js` imports a language file. Logic never glues words, never changes a case and never uses a pronoun or verb form that depends on the thing: a name comes with the forms a sentence needs (`your`, `in`, `at`, `my`) and each sentence is a string or a function in the language file, so a translator can reorder it. Adding a language: copy `en.js`, translate, add a row to `LANGUAGES`. `tests/texts.test.mjs` holds every language to the keys of English and `tests/no-loose-text.test.mjs` fails on a phrase written anywhere else. A move the game refuses is a `RefusedMove` with a code, told with the sentence for that code; any other error is a bug and is rethrown, not shown.

- **The world persists and play happens in days.** The first versions put four things down and asked for them a minute later: short-term memory found them anywhere, so a fixed place earned nothing. Now where a thing lies is where it is next time, also tomorrow (`World.snapshot`/`restore`, saved after every step). A saved day that fails `canContinue` is dropped and the world kept.
- **A day is chains of events, and the app sometimes stays silent** (user design, 2026-11-17, after playing two days: "the game always tells me to put a thing away; in real life nobody does"). Everything starts on its home spot. A chain is a small story with several objects (`app/js/chains/<id>.js`, plain data); a day is an opener and two chains (`day-plan.js`). In about half of the chains the put-back of one thing is left out; if the player does not think of it, a `letGo` event lays the thing on the spot where it was used (`leftAt`), without a word. Later the chain asks "Is everything back in its place?" and **the app never says whether the answer was right**: the player finds out when the thing is needed and is not in its place. For the same reason nothing on a screen names what is in hand, and the day summary does not say what lies where. "Something else first" is on every story screen so the player can put a thing back unasked; it is always there and always the same, so it is no reminder.
- **Objects are things or props.** A chain names every object by id; an id that is a chosen thing is tracked (found, put back, let go), any other is a prop and only told. Making a prop a thing is adding it to the catalogue: the chain file does not change (`STEP_KINDS.expand` decides, tested with the coffee tin). Adding a chain is one file, its sentences in the language file and one row in `CHAINS`; `tests/chains.test.mjs` checks every chain in the list. Adding a kind of step is one row in `STEP_KINDS` (and an event kind in `event-kinds.js` when it needs one). Chains are data modules, not YAML: a static page without dependencies has no YAML reader, and a module is checked by the tests.
- **Stories join where the player is** (story 3c, 2026-11-17, after the user found that sessions stopped feeling natural; three scripted sessions showed jumps between stories, walks back and forth for one sentence, and the same check after every story). Only an opener may start with a `move`; a step is tied to a room (`at`) only when the story needs the place, and only such a step asks the player back; the one check of a session comes at its end, in the closing chain `evening`. The game already is a graph (screens are nodes, choices are edges, the state is stored); these rules keep the edges between stories natural, and the chain contract tests hold every new chain to them. Read a scripted transcript after adding or changing a chain (`play-bot.mjs` in the tests plays a session through `AppFlow`).
- **How hard a day is, is one settings object** (`DEFAULT_RULES` in `day-plan.js`: number of chains, chance of a silent chain, things a chain is silent about). Levels (user idea, later story) are then rows of such settings.
- **Steps are the only currency** (no points): walking to any room costs its distance in one action, looking costs one. A story step ("Go on") is one tap: it is preselected, because a chain has up to ten of them.
- **Removed on purpose:** the round with points and a forced drop (a rule of the game, not of life), and the hurry (the special moment of a day is now the silent chain).

- **The day summary shows the player's own steps** (`history.js` keeps the last 300 finds and put-aways, `summary.js` computes everything from them; nothing derived is stored). A thing that was let go is a put-away record with `left: true`. "Going straight to each thing" is the shortest way to where each thing really lay, measured from the room where the find began plus one look: it is what knowing the place would have cost, not what the home spot would have cost, and the sentence says so. The come-back-tomorrow line shows when a day is finished on the same date as the one before (`Clock` port, `lastDayFinishedOn`), decided at the finish so a reload cannot lose it.

- **The player says "session", the code says "day"** (user wording, 2026-11-17). Every session opens with a pause that says whether it is a new game ("A new game. Everything is in its home spot.", only session 1) or a game that goes on ("Everything is where you left it."): the player has to know whether the world starts clean or carries things over.
- **Looking back is read only** (user request, 2026-11-17: "I want to be able to go back to an earlier card, to look back"). A quiet "Look back" link next to "Menu" opens the screens of the current session, newest first, each with what was chosen on it; only "Earlier screen", "Later screen" and "Back to the game" are offered, and nothing is redone, because redoing would break the world that carries over. The log (`screen-log.js`, 60 screens) lives in memory: it starts empty with every new session and after a reload, and a Next that did nothing is not a screen left. **Known tension, to be judged by playing:** an earlier screen says what you took ("Found your scissors"), which is exactly what a silent chain leaves out. Possible later answers: look back only within the running chain, or not past a check question.
- **Home spots are changed from a list, and the game can be started again** (user requests, 2026-11-17). Choosing home spots opens a list of the things with where each lives now; any thing can be changed first and the rest stay as they are, so nobody is made to set every thing; "I am done" leaves. "Start again" is on the start screen only once a session has been started (a new game has nothing to erase), asks first, and erases sessions, streaks, history, the world and the day in progress but **keeps the home spots** (the player's own choices, easy to change from the list); every thing is then on its home spot again. The erased state is saved at once, so a reload cannot bring the old game back.
- **Core logic has no DOM, no `Date.now()`, no `Math.random()`**: time, randomness and storage come in through ports, so every scenario is a deterministic unit test.
- **Wrong places are cheap and tempting on purpose.** Research on habit cues shows people pick the cue that costs the least effort, so the nearest place must be the easy one and the home spot the one that costs an extra step.
- **No hints while playing** (user decision 2026-11-17, replacing the fading hints: "a star at the home spot meant I could no longer choose from my own memory"). Nothing points at a home spot while playing: no star on a spot, pocket or room, no "Your plan" line. The feedback after a stray placement (with the home spot) stays: it comes after the act. The star in the home-spot list stays: that is choosing, not playing. The streaks are still kept for a later progress screen.
- **One tap by default, two taps as a setting** (user request, 2026-11-17: "pushing Next slows the game down"). `AppFlow.tap` chooses and, with `oneTap` on, acts at once; screens with choices then have no Next button and show no selection (a preselected "Go on" would look like a choice already made). A pause keeps its Next. The setting is on the start screen under "Settings", saved, and survives "Start again".
- **Praise for a thing put on its home spot** (user request, 2026-11-17: "a good action should be rewarded: conspicuous, green, modest"). The next screen shows "✨ Well done! ..." in a soft green box above the lead, with a short fade-in that `prefers-reduced-motion` switches off. Nothing that the app keeps silent about is praised: no praise for a find, for "Yes, everything", or for a stray placement.
